# Quickstart: 007-web-bbs-write 検証ガイド

**Feature**: 007-web-bbs-write | **参照**: [plan.md](plan.md)、[contracts/](contracts/)

本機能(旧来 BBS 互換 Web UI・LAN 公開・固定 >>1)が端から端まで動くことを確認する
手順。実装詳細は tasks.md と各 contract を参照。

## 前提

- Rust stable toolchain(edition 2024 対応)
- 稼働端末 1 台(V-3 以降は同一 LAN 上の別端末 1 台 — スマホ/別 PC — と、可能なら
  2ch 互換専ブラを追加)
- 006 の機能(スレ開設・書き込み・互換 API)が動作するブランチ

## ビルドと自動テスト

```powershell
cargo fmt -- --check
cargo clippy --all-targets
cargo test                       # unit + contract + integration + cucumber
cargo test --test livechat       # 固定 >>1(自動投稿・次スレ・遡及なし)
cargo test --test cli_config     # LAN bind 許可リスト・同意キー検証
cargo test --test compat_bbs     # 互換 API の Host/送信元検証境界
cargo test --test lan_write      # LAN 公開時の非 loopback 読み書き(新規)
```

**期待**: すべてパス(ネガティブシナリオ含む)。

## V-1: 旧来 BBS 互換 Web UI(US1 / SC-001)

1. 既定設定(loopback のみ)で起動し、稼働端末のブラウザで
   `http://127.0.0.1:7180/livechat.html` を開く
2. 板ページを表示 → **期待**: スレ一覧・新規スレ作成欄・ローカルルール掲示が参考画像
   `assets/bbsjpnkn_board_alt.png` と同等の要素構成で表示される
3. スレを開いて閲覧 → **期待**: `{res_no} :{名前}:{日付} ID:{id}` 形式のレス列
   (既定 最新 50)。名前空欄のレスは名無しデフォルト名で表示される
4. 本文に `>>1` を含む書き込みを投稿 → **期待**: 202 受理後、ポーリングでレス列に反映。
   `>>1` はクリックでジャンプ・ホバーでポップアップ表示。存在しない `>>9999` は
   「解決不能」表示になる
5. 本文に `<script>alert(1)</script>` を投稿 → **期待**: テキストとして表示され実行
   されない(FR-005)
6. 大量レス時の描画(plan Performance Goals): res_limit 上限相当(4000 レス)を投入
   したスレで「全部読む」を選択 → **期待**: 初回描画が 5 秒以内に完了し、スクロールと
   `>>n` ジャンプが応答する(操作不能・ブラウザのハングが起きない)。レス投入は互換 API
   (bbs.cgi)へのスクリプト連投等で行ってよい(per-IP レート制限 20 req/秒に注意)

## V-2: 固定 >>1(US3 / SC-005・SC-006)

1. 板設定で `first_post_template` に配信 URL 入りの定型文を設定して保存
2. 新規スレを開設 → **期待**: 開設直後のスレに >>1 がテンプレ本文で確定表示され、
   `>>1` アンカーが解決する
3. 明示操作で次スレへ移行 → **期待**: 新スレの >>1 に同じテンプレが自動投稿される
4. テンプレを別の文言へ変更 → 次スレを開始 → **期待**: 新スレの >>1 は新テンプレ、
   既存スレの >>1 は元のまま(遡及 0 件)
5. テンプレを空にして新規スレを開設 → **期待**: 板タイトル・チャンネル案内のシステム
   既定テンプレで >>1 が自動投稿される(空 >>1 なし)
6. プロセスを再起動して次スレを開始 → **期待**: テンプレが永続化されており同様に
   自動投稿される

## V-3: LAN 公開 — Web UI(US2 / SC-002・SC-003・SC-004)

1. 稼働端末の LAN アドレス(例 `192.168.1.10`)を確認し、設定で
   `http_bind = 192.168.1.10:7180` を指定する
   - まず `http_lan_consent` を立てずに起動 → **期待**: 設定エラーで公開されない
   - 設定 UI 経由の場合 → **期待**: 平文・実質無認証リスクの警告と明示確認が出る
2. `http_lan_consent = true` で起動 → **期待**: 起動成功、SecurityEvent
   `WebUiLanExposed` が 1 件記録される
3. 別端末のブラウザで `http://192.168.1.10:7180/livechat.html` を開く →
   **期待**: 板ページ・スレページが表示され、書き込みができる
4. 別端末からの書き込みが、稼働端末側と同一レス番号・同一並びで確定する(SC-002/SC-007)
5. 拒否確認(SC-003): `http_bind` に以下を指定して起動 → **期待**: いずれも設定エラー
   - `0.0.0.0:7180`(未指定)
   - `100.64.1.2:7180`(CGNAT)
   - グローバルアドレス(例 `203.0.113.5:7180`)
6. LAN 公開中に `curl -H "Host: evil.example:7180" http://192.168.1.10:7180/...` →
   **期待**: 403(ホワイトリスト外 Host)
7. 既定設定(loopback)に戻す → **期待**: 別端末から到達できない(現状維持)

## V-4: LAN 公開 — 2ch 互換 API(US2 / SC-009)

1. `compat_bbs_bind = 192.168.1.10:7183` + `compat_bbs_lan_consent = true` で起動 →
   **期待**: SecurityEvent `CompatBbsLanExposed` が 1 件記録される
2. 別端末の専ブラに板 URL `http://192.168.1.10:7183/{board}/` を無改修で登録 →
   **期待**: スレ一覧取得(subject.txt)・レス取得(dat)・書き込み(bbs.cgi)が成立する
3. その書き込みが全端末で同一レス番号として確定する
4. 拒否確認: `compat_bbs_bind` にグローバル/CGNAT/`0.0.0.0` を指定 → **期待**: 設定エラー
5. Web UI の板ページに掲示される専ブラ向け板 URL が、閲覧元ホスト名 + 互換ポートで
   動的生成されている(loopback ハードコードでない)ことを確認する

## V-5: 保護の非緩和(SC-008)

1. LAN 公開中、別端末から同一送信元で 20 req/秒を超えるリクエストを送る →
   **期待**: 429(loopback と同一上限)
2. 過大ボディ(互換 API 64KB 超)を送る → **期待**: 拒否(loopback と同一)

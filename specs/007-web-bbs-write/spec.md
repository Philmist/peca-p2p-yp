# Feature Specification: Web ブラウザからの実況スレ書き込み(旧来 BBS 互換 UI・LAN 公開・固定 >>1)

**Feature Branch**: `007-web-bbs-write`

**Created**: 2026-07-31

**Status**: Draft

**Input**: User description: "一部 2ch 互換 BBS ブラウザで書き込みができるようになったが、現状の機能では他の Web ブラウザから書き込む時に実装が不十分であることが判明した。具体的には (1) UI(HTML/CSS)デザインと機能が旧来の物と合致しない、(2) 視聴端末と本ソフトウェア稼動端末が同一でない場合書き込むことが出来ない、(3) スレ立て後の >>1 が常に空(そもそも >>1 がない)である。これらを解消したい。旧来 BBS のデザイン参考: `assets/bbsjpnkn_board_alt.png` / `assets/bbsjpnkn_thread_last50_alt.png`。現代的 BBS のデザイン参考: `assets/bbsjpnkn_board_main.png` / `assets/bbsjpnkn_thread_last50_main.png`。"

## 背景 *(context)*

006-livechat-thread により、配信実況スレ(P2P 掲示板)の中核 — スレ開設・順序確定・
書き込み・モデレーション・板設定 — と、既存の 2ch 互換クライアント(専ブラ・コメント
ビューワ)向けの loopback 互換 API(subject.txt / dat / SETTING.TXT / bbs.cgi 相当、
Shift_JIS)が成立した。一部の 2ch 互換 BBS ブラウザからの読み書きは実機で確認済みである。

しかし、専ブラを使わない大多数の視聴者が到達する経路 — **本ソフトウェア同梱の Web UI**
(`ui/livechat.html`) — は管理操作用の素朴な表組みに留まっており、実況の場として使うには
以下の 3 点が不足していることが判明した。

1. **UI(HTML/CSS)デザインと機能が旧来の物と合致しない**: 現行 Web UI は一覧表と
   フォームの寄せ集めで、伝統的な掲示板(スレ一覧・スレ立てフォーム・ローカルルール掲示・
   名前/メール/本文の書き込み欄・レス番号/ID/日付の並び・`>>n` アンカー)としての
   見た目と操作感を備えていない。実況利用者が「掲示板」として即座に理解できない。
2. **視聴端末と稼働端末が同一でない場合に書き込めない**: Web UI(`http_bind`、既定
   `127.0.0.1:7180`)も互換 API(`compat_bbs_bind`、既定 `127.0.0.1:7183`)も loopback
   強制であり、本ソフトウェアが動く PC 以外の端末(視聴に使うスマホ・タブレット・別 PC)の
   ブラウザからは到達できない。実況は「配信画面を見ている端末」から書き込みたい場面が多く、
   稼働端末に張り付く前提は実勢に合わない。
3. **スレ立て後の >>1 が常に空(そもそも >>1 がない)**: スレ開設はチャンネルとタイトル
   のみを受け取り、最初のレス(>>1)を生成しない。確定レス列は 1 番から欠番なく積まれる
   ため、最初の書き込みが来るまでスレは本文ゼロで、`>>1` を指すアンカーも解決先を持たない。
   参考画像(`_alt`)が示すとおり、伝統的な実況スレの >>1 は配信 URL や各種リンクを載せた
   定型のスレ主投稿であり、その不在は掲示板としての体裁を欠く。

本機能は、006 の P2P・順序確定・検証・互換 API という土台を一切変更せず、その上の
**表現層(Web UI)と公開経路(バインド)と開設時の初期状態(>>1)** を旧来 BBS の実勢に
合わせて補うものである。P2P プロトコル・順序確定・鍵体系・NG/BAN・PoW・レート制限は
006 の設計をそのまま踏襲する。

### 用語(006 からの差分)

| 用語 | 意味 |
|------|------|
| **Web UI** | 本ソフトウェア同梱の、専ブラを持たない利用者向けのブラウザ画面(`ui/livechat.html` の後継)。板ページ(スレ一覧 + スレ立て + ローカルルール)とスレページ(レス列 + 書き込み欄)からなる |
| **旧来スキン** | 参考画像 `_alt`(レンガ背景・緑帯・`1 :名前 :日付 ID:xxx` 形式のレス列)に相当する伝統的 2ch 風の見た目。本機能で主として採用する |
| **視聴端末** | 配信を視聴している端末。本ソフトウェアが稼働する端末(稼働端末)と同一とは限らない。同一 LAN 上の別端末を含む |
| **LAN 公開** | Web UI とその JSON API、および 2ch 互換 API を loopback だけでなく LAN 内プライベートアドレス(RFC 1918 / リンクローカル / ULA)にも待ち受けさせる、明示オプトインの公開設定。ADR-0012(読み取り専用 index.txt の LAN 公開)の許可リスト方式に準拠しつつ、**書き込みを含む**点が新しい。互換 API はトークンを持てないため LAN 書き込みは無認証で、保護は Host 検証・レート制限・LAN 内アドレス限定・明示オプトイン・監査で担保する |
| **固定 >>1(スレ頭テンプレ)** | 板主が板設定として事前に指定する、スレ開設時に自動で >>1 として書き込まれる定型本文。次スレ移行時にも同様に自動投稿される。確定済みレスの不変性(006 FR-023)により、テンプレ変更は既存スレの >>1 に遡及しない |

## Clarifications

### Session 2026-07-31

- Q: Web UI のデザイン方針は(参考 `_alt`=旧来 / `_main`=現代的)? → A: **旧来(`_alt`)を主とする**。伝統的 2ch 風のスキンを標準として実装する(現代的スキンは本機能のスコープ外)
- Q: 視聴端末(別端末)からの書き込みを可能にする公開方針は? → A: **LAN 内プライベートアドレスのみ公開(ADR-0012 準拠)**。loopback + RFC 1918 / リンクローカル / ULAへの bind のみ許可し、グローバル公開はしない。追加の別途認証(PIN 等)は課さず、LAN 内を信頼境界とする
- Q: スレ立て時の最初のレス(>>1)の内容は? → A: **コミュニティの実況では >>1 が固定であることが多いため、>>1 の内容を板設定として事前指定し、スレ立て後は >>1 が自動で書き込まれた状態にする**(固定 >>1・スレ頭テンプレ)
- Q: 2ch 互換 API(専ブラ向け)の使用スコープも LAN へ広げるか。広げる場合、互換 API は設計上トークンを送れないため LAN 書き込みの保護をどうするか? → A: **互換 API も LAN 公開の対象に含める**。LAN 内を信頼境界とし、互換 API の LAN 書き込みは**無認証**を許容する。保護は Host 検証 + per-IP レート制限 + LAN 内アドレス限定(loopback / RFC 1918 / リンクローカル / ULA)+ 明示オプトイン + 起動時 SecurityEvent 記録で担保する(HTML UI と同一方針・ADR-0012 準拠)。既定は loopback のみ

### Session 2026-08-03

- Q: 専ブラ向け板 URL `.../{board}/` をブラウザで開いたときの挙動は(2ch 流儀: `subject.txt` は専ブラが読み、`.../{board}/` はブラウザで板ページ)? → A: **互換 API ポートが `.../{board}/` を旧来 BBS UI の板ページ(HTML)として自ら配信する**。`.../{board}/subject.txt`・`dat`・`bbs.cgi` は従来どおり専ブラ向け(Shift_JIS)、ブラウザ向け HTML は UTF-8。同一ポート・パスで振り分け、リダイレクトはしない(一貫性のため)
- Q: 板設定・モデレーションの編集導線は(スレを立てないと管理できない問題)? → A: **設定はスレから切り離し板ページから、モデレーション実行はスレページから(スレを見ながら)**。板設定(タイトル・名無し名・ローカルルール・固定 >>1 テンプレ)はスレの有無に関係なく板ページから編集可能とする。個別レスへの NG/BAN 等の実行はスレページ起点。ただし **BAN 済みの一覧は板設定から表示・変更(解除等)できる**
- Q: 新規スレ開設時に >>1 をその場で設定・書き込みできるべきか(固定テンプレがあれば代替可)? → A: **固定 >>1 テンプレを既定値としてフォームにプリフィルし、任意でその場編集(上書き)可**。未編集なら従来どおり固定テンプレが >>1 として自動確定する(空 >>1 は生じない)。その場上書きは固定テンプレの永続値を変更しない(そのスレ限り)
- Q: スレ一覧→スレ・板一覧→自板の遷移リンク欠落(#2/#3)を必須要件化するか? → A: **両方を必須化**。スレ一覧の各スレ項目はそのスレページへ、板一覧(板の入口)の各板項目は自板の板ページへ、クリックで遷移できるリンクを持つ

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 旧来 BBS 互換の Web UI で読み書きする (Priority: P1)

専ブラを持たない視聴者として、本ソフトウェアの Web UI を開くだけで、見慣れた掲示板と同じ
見た目・操作感で実況スレを読み、書き込みたい。スレ一覧からスレを選び、レス番号・ID・日付が
並んだ本文を読み、`>>152` のようなアンカーをたどり、名前・メール・本文を入力して書き込む、
という一連の体験が「掲示板そのもの」として成立してほしい。

**Why this priority**: 専ブラ利用者は既に 006 でカバー済みで、Web UI が唯一の経路である
多数派(スマホ視聴者等)にとって、現行の管理表 UI は掲示板として認識できない。表現層が
旧来 BBS に合致しなければ、実況の場として機能しない。

**Independent Test**: 稼働端末 1 台で Web UI を開き、スレ一覧の表示・スレ立て・スレ閲覧
(レス番号/名前/ID/日付/本文/アンカーの並び)・書き込み・書き込み後の反映、および
ローカルルールの掲示が、参考画像 `_alt` と同等の要素構成で成立することを単体で検証できる。

**Acceptance Scenarios**:

1. **Given** 稼働端末で Web UI を開いた利用者、**When** 板ページを表示する、**Then** スレ一覧・新規スレ作成欄・ローカルルール掲示が、伝統的な掲示板のレイアウト(参考 `_alt`)で表示される
2. **Given** スレを開いた利用者、**When** レスを閲覧する、**Then** 各レスがレス番号・名前・ID・日付・本文の並び(伝統的 2ch 形式)で表示され、本文中の `>>n` がアンカーとして機能する(参照先レスへの移動やポップアップ等の到達手段がある)
3. **Given** スレを開いた利用者、**When** 名前・メール・本文を入力して書き込む、**Then** 書き込みは 006 と同一の経路・検証を通り、確定後に同じ画面のレス列へ反映される
4. **Given** 名前欄を空のまま書き込んだ利用者、**When** レスが確定表示される、**Then** 板の名無しのデフォルト名で表示される(006 FR-024 の挙動を UI が正しく提示する)
5. **Given** 板主がローカルルール(Markdown)を設定済み、**When** 利用者が板ページを開く、**Then** ローカルルールが安全な描画(HTML/スクリプト非実行 — 006 FR-025)で掲示される
6. **Given** 進行中のスレを閲覧中の利用者、**When** 他の参加者の確定レスが増える、**Then** 明示更新または定期更新で新しい確定レスが追従表示される

### User Story 2 - 視聴端末(別端末)から書き込む (Priority: P1)

配信をスマホ/タブレット/別 PC で視聴している利用者として、その視聴端末のブラウザ
(Web UI)または使い慣れた専ブラ(2ch 互換 API)から、同一 LAN 上で稼働している本
ソフトウェアの実況スレを読み書きしたい。稼働端末(配信 PC 等)にわざわざ移動しなくても、
いま配信を見ている端末からそのまま実況に参加したい。

**Why this priority**: 「配信を見ている端末から書き込む」は実況の基本動線であり、
loopback 強制のままでは視聴端末=稼働端末という非現実的な前提を強いる。US1 の UI 改善が
あっても、到達できなければ多数派の視聴者は書き込めない。

**Independent Test**: 稼働端末 + 同一 LAN 上の別端末の 2 台で、別端末の Web ブラウザ
および専ブラ(2ch 互換 API)からスレ一覧閲覧・スレ閲覧・書き込みが成立し、その書き込みが
稼働端末側・全参加者で同一レス番号として確定することを検証できる。あわせて、グローバル/
CGNAT アドレスへの公開設定が拒否されることを検証できる。

**Acceptance Scenarios**:

1. **Given** 利用者が Web UI の LAN 公開を明示的に有効化(LAN 内プライベートアドレスへ bind)している、**When** 同一 LAN 上の別端末のブラウザからその LAN アドレスへアクセスする、**Then** 板ページ・スレページが表示され、書き込みができる
2. **Given** LAN 公開が無効(既定 = loopback のみ)、**When** 別端末からアクセスする、**Then** 到達できない(既定は稼働端末からのみ)
3. **Given** 利用者が公開先にグローバルユニキャスト/未指定(0.0.0.0)/CGNAT アドレスを指定した、**When** 起動・設定適用する、**Then** その公開設定は拒否され、LAN 公開は成立しない(loopback + RFC 1918 / リンクローカル / ULAのみ許可)
4. **Given** 利用者が「LAN 内で平文・(LAN 内共有トークンにより)無認証相当のまま読み書きされうる」旨のリスクへの明示確認(同意)を済ませて非 loopback 待受を設定した、**When** 起動が完了し待受に成功する、**Then** 公開の事実がセキュリティイベントとして記録される(明示確認なしには非 loopback 待受は成立しない)
5. **Given** 別端末から届いた書き込み、**When** ホストが採番する、**Then** 006 と同一の検証(サイズ・形式・署名・PoW・レート制限・名前欄の `#` 除去)を通り、全端末で同一レス番号・同一並びに確定する(006 の全端末一致は維持される)
6. **Given** LAN 公開時の受信、**When** 過大 URL/ヘッダ・レート超過が来る、**Then** loopback 側と同一の上限(緩和なし)で拒否される(ADR-0012 決定 5 に準拠)
7. **Given** 2ch 互換 API の LAN 公開を明示的に有効化している、**When** 同一 LAN 上の別端末の専ブラをその LAN アドレスへ向けて無改修で読み書きする、**Then** スレ一覧取得・レス取得・書き込みが成立し、書き込みは 006 と同一の検証を経て全端末で同一レス番号に確定する
8. **Given** 互換 API はトークンを送れないため LAN 書き込みが無認証である、**When** LAN 内の別端末から書き込む、**Then** Host 検証・per-IP レート制限・LAN 内アドレス限定により受理範囲が LAN 内に限定され、それ以外(グローバル/CGNAT/ホワイトリスト外 Host)からは受理されない

### User Story 3 - スレ立てで固定 >>1 が自動投稿される (Priority: P1)

配信者(板主)として、スレ立てのたびに毎回同じ案内(配信 URL・視聴方法・各種リンク・
注意書き)を >>1 に載せたい。その内容を板設定として一度用意しておけば、スレを立てた瞬間に
>>1 として自動で書き込まれ、次スレへ移行したときも同じ >>1 が自動で置かれてほしい。
視聴者として、スレを開いたら必ず >>1 にスレの案内があってほしい(空の >>1 や >>1 不在で
困りたくない)。

**Why this priority**: >>1 の不在は「スレ立て後の >>1 が常に空」という報告の核心であり、
掲示板としての体裁(スレ頭の案内・`>>1` アンカーの解決先)を直接欠く。固定 >>1 は実況
コミュニティの実勢(スレ頭テンプレ)に一致し、開設のたびの手作業を不要にする。

**Independent Test**: 板主が固定 >>1 テンプレを設定した板で、スレ開設 → >>1 が自動で
確定表示される → 次スレ移行 → 新スレの >>1 に同じテンプレが自動で置かれる、を検証できる。
テンプレ変更が既存スレの >>1 に遡及しないことも検証できる。

**Acceptance Scenarios**:

1. **Given** 板主が固定 >>1 テンプレ本文を板設定に指定済み、**When** その板でスレを開設する、**Then** スレ開設と同時に >>1 がテンプレ本文で自動確定し、開いた全参加者に >>1 として表示される
2. **Given** 固定 >>1 が自動投稿されたスレ、**When** 参加者が `>>1` アンカーをたどる、**Then** 自動投稿された >>1 に解決する(スレ開設直後から `>>1` が解決先を持つ)
3. **Given** 進行中スレが次スレへ移行した(レス上限到達または明示操作)、**When** 新スレが開始する、**Then** 新スレの >>1 に同じ固定テンプレが自動で置かれる
4. **Given** 板主が固定 >>1 テンプレを変更した、**When** 変更後に新しいスレ(または次スレ)が開始する、**Then** 新スレの >>1 は新テンプレになり、既存の確定済みスレの >>1 は元のまま(遡及しない — 006 FR-023 の確定済みレス不変性)
5. **Given** 固定 >>1 テンプレが未設定(空)の板、**When** スレを開設する、**Then** >>1 は空にならず、システム既定の最小テンプレ(板タイトル/対象チャンネルの案内)で自動投稿される(空 >>1 を生じさせない)
6. **Given** 自動投稿された >>1、**When** 参加者側で検証・表示する、**Then** >>1 は板主(スレ主)由来として整合的に確定・表示され、通常の参加者書き込みと同じ検証を満たす(不正な >>1 は生じない)

### Edge Cases

- **UI 描画の安全性**: レス本文・名前・メール・ローカルルール・固定 >>1 テンプレに HTML/
  スクリプトが含まれても、Web UI は描画・実行しない(006 FR-025 の安全描画を UI 側でも
  一貫して適用する)
- **アンカーの解決先が未確定/欠番**: `>>n` が未確定・欠番(NG 非表示を含む)・範囲外を指す
  場合、UI は誤ったレスへ誘導せず、解決不能であることを示す(006 の欠番維持と整合)
- **LAN 公開時のトークン取り扱い**: 別端末ブラウザは書き込みに必要なセッショントークンを
  取得できる必要があるが、それは LAN 内で平文共有される。これは LAN を信頼境界とする本
  設計の受容リスクであり、明示確認とセキュリティイベント記録の対象とする(グローバル公開は
  しないため露出は LAN 内に限られる)
- **公開設定の境界値**: v4-mapped IPv6 で表現されたプライベートアドレスは正規化して判定する
  (loopback/private の誤判定防止 — 既存の正規化方針に従う)。100.64.0.0/10(CGNAT)は
  グローバル扱いで拒否する
- **固定 >>1 と res_limit**: 自動投稿の >>1 はレス番号 1 を占有し、レス上限(006 の
  100〜4000)にカウントされる。上限計算・次スレ移行判定は >>1 を含めて一貫する
- **固定 >>1 と初回 PoW**: 板主(スレ主)自身による >>1 の自動投稿には参加者向けの初回
  PoW(006 FR-017)を課さない(ホスト自身の採番であり、荒らし対策の対象外)
- **固定 >>1 テンプレの検証**: テンプレ本文は板設定の一部として受信時に検証する(サイズ
  上限・安全描画対象)。上限超過等の不正なテンプレは 006 の板設定検証と同様に扱う
- **旧来スキンの機能範囲**: レンガ背景等の装飾は見た目の範囲であり、書き込みの検証・順序
  確定・NG/BAN 等の機能的挙動は 006 のまま変わらない(スキンは表現層のみ)
- **専ブラ互換 API の LAN 無認証書き込み**: 互換 API はトークンを送れないため、LAN 公開時の
  書き込みは無認証で受理される。これは LAN を信頼境界とする本設計の受容リスクであり、
  Host 検証・per-IP レート制限・LAN 内アドレス限定・明示オプトイン・起動時 SecurityEvent
  記録で補償する(HTML UI と同一方針)。グローバル公開はしないため露出は LAN 内に限られる
- **公開面ごとのオプトイン**: Web UI(+JSON API)と 2ch 互換 API はそれぞれ独立に LAN 公開の
  可否を設定でき、いずれも既定は loopback のみ(具体的な設定単位は plan で確定)
- **視聴端末が LAN 外**: モバイル回線等 LAN 外の端末からの書き込みは本機能のスコープ外
  (グローバル公開はしない)。将来的な遠隔公開は別途の設計課題とする

## Requirements *(mandatory)*

### Functional Requirements

**Web UI(旧来 BBS 互換の表現・機能)**

- **FR-001**: Web UI は伝統的な掲示板(参考画像 `_alt` 相当)の要素構成 — 板ページ(スレ一覧・新規スレ作成・ローカルルール掲示)とスレページ(レス番号・名前・ID・日付・本文の並び、名前/メール/本文の書き込み欄)— を提供しなければならない (MUST)
- **FR-002**: Web UI は各レスを伝統的 2ch 形式(レス番号 + 名前 + ID + 日付 + 本文)で表示し、本文中の `>>n` アンカーから参照先レスへの到達手段(移動・ポップアップ等)を提供しなければならない (MUST)
- **FR-002a**: Web UI は一覧からの遷移リンクを提供しなければならない (MUST) — スレ一覧の各スレ項目はそのスレページへ、板一覧(板の入口)の各板項目は自板の板ページへ、それぞれクリックで遷移できなければならない。一覧項目を遷移手段のない静的表示に留めてはならない (MUST NOT)(参考 `_alt` の掲示板と同等のナビゲーション)
- **FR-003**: Web UI からの書き込みは 006 の通常書き込みと同一の経路・検証(署名・PoW・レート制限・名前欄の `#` 除去・サイズ上限)を通らなければならない (MUST)。Web UI 専用の検証の抜け道を作ってはならない (MUST NOT)
- **FR-004**: Web UI は板設定(板タイトル・名無しのデフォルト名・ローカルルール)を旧来 BBS の掲示形式で提示し、名前空欄時の名無し表示など 006 の表示挙動を正しく反映しなければならない (MUST)
- **FR-005**: Web UI はレス本文・名前・メール・ローカルルール・固定 >>1 を安全に描画し、HTML の直接埋め込みやスクリプトの実行を許可してはならない (MUST NOT)(006 FR-025 と一貫)
- **FR-006**: Web UI は進行中スレの新しい確定レスを追従表示できなければならない (MUST)(明示更新または定期更新)
- **FR-006a**: Web UI は板設定(板タイトル・名無しのデフォルト名・ローカルルール・固定 >>1 テンプレ)の編集を、スレの有無・スレ開設操作と独立に**板ページ**から到達・実行できるようにしなければならない (MUST)。板設定の編集をスレ開設や特定スレの存在に依存させてはならない (MUST NOT)(スレ 0 件の板でも管理可能であること)
- **FR-006b**: 個別レスに対するモデレーション実行(NG/BAN 等)は、対象を閲覧しながら操作できるよう**スレページ**を起点に提供してよい (MAY)。一方、BAN 済みエントリの**一覧参照および変更(解除等)** は板設定(板ページ)から到達・実行できるようにしなければならない (MUST)(モデレーションの実行面と管理面を分離しつつ、BAN 台帳はスレに依存せず参照可能とする)

**視聴端末(別端末)からの到達 = LAN 公開**

- **FR-007**: 利用者は Web UI とその JSON API、および 2ch 互換 API を、loopback に加えて LAN 内プライベートアドレス(RFC 1918 / リンクローカル / ULA)へ待ち受けさせる公開設定を、明示オプトインで有効化できなければならない (MUST)。既定はいずれも loopback のみ(現状維持)でなければならない (MUST)。FR-008〜FR-011 の公開規律(アドレス許可リスト・Host 検証・明示確認と監査・保護の非緩和)は Web UI と 2ch 互換 API の双方に等しく適用しなければならない (MUST)
- **FR-008**: LAN 公開の待受アドレスは loopback / RFC 1918 / リンクローカル / ULA(`fc00::/7` — IPv6 における RFC 1918 相当のプライベートアドレス)のみ許可しなければならない (MUST)。グローバルユニキャスト・未指定(0.0.0.0 / ::)・CGNAT(100.64.0.0/10)への公開は拒否しなければならない (MUST NOT)。アドレス判定は正規化(v4-mapped 等)してから行わなければならない (MUST)
- **FR-009**: Host ヘッダ検証のホワイトリストは、公開した LAN アドレスを含むよう構成し、ホワイトリスト外・欠落は拒否しなければならない (MUST)(DNS rebinding / CSRF 対策の維持)
- **FR-010**: 非 loopback での LAN 公開設定には、「LAN 内で平文・LAN 内共有トークンにより実質無認証のまま読み書きされうる」旨のリスクへの明示確認を必須とし (MUST)、非 loopback で待受に成功した起動時にセキュリティイベントを記録しなければならない (MUST)(ADR-0012 決定 3 に準拠)
- **FR-011**: LAN 公開時も、URL/ヘッダサイズ上限・per-IP レート制限その他の保護を loopback 側と同一水準で維持しなければならない (MUST)。LAN 公開を理由に保護を緩和してはならない (MUST NOT)(ADR-0012 決定 5 に準拠)
- **FR-012**: 別端末からの書き込みも 006 の順序確定を満たし、全端末でレス番号・並び順・アンカー解決が一致しなければならない (MUST)(書き込み元の端末が稼働端末か別端末かによって挙動が変わってはならない — MUST NOT)

**固定 >>1(スレ頭テンプレ)**

- **FR-013**: 板主は固定 >>1(スレ頭テンプレ)本文を板設定として事前に指定できなければならない (MUST)。テンプレは板設定の一部として配布・検証(サイズ上限・安全描画対象)されなければならない (MUST)
- **FR-014**: スレ開設時、システムは指定された固定 >>1 テンプレをレス番号 1 として自動的に確定・配布しなければならない (MUST)。スレ開設直後から `>>1` は解決先を持たなければならない (MUST)。空の >>1・>>1 不在の状態を生じさせてはならない (MUST NOT)
- **FR-014a**: 新規スレ開設フォームは固定 >>1 テンプレ(未設定時はシステム既定テンプレ)を >>1 本文の既定値としてプリフィル表示し、板主が開設時に任意でその場編集(上書き)できるようにしなければならない (MUST)。未編集の場合は既定値(固定/システム既定テンプレ)がそのまま >>1 として確定しなければならない (MUST)。その場上書きは当該スレの >>1 にのみ反映され、板設定に永続化された固定 >>1 テンプレの値を変更してはならない (MUST NOT)。上書き後の >>1 も FR-016 と同一の検証(採番・署名・配布、初回 PoW 免除)を満たさなければならない (MUST)
- **FR-015**: 次スレへの移行(レス上限到達または明示操作)時も、システムは新スレの >>1 に固定テンプレを自動投稿しなければならない (MUST)
- **FR-016**: 固定 >>1 の自動投稿は板主(スレ主)由来として整合的に採番・署名・配布され、通常の書き込みと同一の検証を満たさなければならない (MUST)。自動 >>1 に参加者向けの初回 PoW を課してはならない (MUST NOT)
- **FR-017**: 固定 >>1 テンプレの変更は、変更後に開始するスレ(次スレを含む)から適用しなければならない (MUST)。既存の確定済みスレの >>1 に遡及してはならない (MUST NOT)(006 FR-023 の確定済みレス不変性)
- **FR-018**: 固定 >>1 テンプレが未設定(空)の場合、システムはシステム既定の最小テンプレ(板タイトル・対象チャンネルの案内)で >>1 を自動投稿しなければならない (MUST)(空 >>1 を生じさせない)
- **FR-019**: 固定 >>1 はレス番号 1 を占有し、レス上限(006 の 100〜4000)にカウントされ、次スレ移行判定に一貫して含めなければならない (MUST)

**2ch 互換 API の LAN 公開**

- **FR-020**: 2ch 互換 API(スレ一覧・スレ本文・板設定・書き込み)は LAN 公開の対象に含め、別端末の専ブラが無改修で読み書きできなければならない (MUST)。既定は loopback のみでなければならない (MUST)
- **FR-021**: 互換 API は設計上トークンを送れないため、LAN 公開時の書き込みは無認証で受理してよい (MAY)。ただし受理範囲は Host 検証・per-IP レート制限・LAN 内アドレス限定(loopback / RFC 1918 / リンクローカル / ULA)により LAN 内へ限定しなければならず (MUST)、グローバル/CGNAT/未指定アドレス・ホワイトリスト外 Host からは受理してはならない (MUST NOT)
- **FR-022**: 互換 API 経由の LAN 書き込みも 006 の通常書き込みと同一の経路・検証(板鍵での自動署名・名前欄の `#` 除去・PoW・レート制限・サイズ上限)を通らなければならない (MUST)。互換経路の LAN 公開を理由に検証や保護を緩和してはならない (MUST NOT)(006 FR-028・ADR-0012 決定 5 と一貫)
- **FR-023**: 互換 API を提供する待受面は、専ブラ向けパス(`.../{board}/subject.txt` / `dat` / `bbs.cgi` 相当)に加えて、板ルート URL `.../{board}/`(ファイル名を伴わないパス)への Web ブラウザからのアクセスに対し、旧来 BBS UI の板ページ(HTML)を同一ポート・同一パス上で自ら配信しなければならない (MUST)(2ch の実勢 — 専ブラは `subject.txt` を読み、ブラウザは `.../{board}/` で板を開く — に従う)。振り分けはパスで行い、専ブラ向けレスポンスは従来どおり Shift_JIS、ブラウザ向け HTML は Web UI と同じ表現層・文字コードとしなければならない (MUST)。板ルート URL のブラウザ向け配信を他の待受面(`http_bind` 等)への HTTP リダイレクトで代替してはならない (MUST NOT)(専ブラと同一 URL 上での自己完結・一貫性の維持)

### Key Entities

- **Web UI ページ**: 板ページ(スレ一覧・新規スレ作成・ローカルルール掲示)とスレページ(レス列・書き込み欄)。旧来 BBS 互換の表現層。属性: 対象板、表示スキン(旧来)、提示する板設定
- **LAN 公開設定**: Web UI + JSON API、および 2ch 互換 API の公開範囲(公開面ごとに独立)。属性: 待受アドレス(loopback または LAN 内プライベート)、明示オプトインの確認状態、Host ホワイトリスト、互換 API の無認証書き込み許容(LAN 内限定)。既定はいずれも loopback のみ
- **固定 >>1 テンプレ(スレ頭テンプレ)**: 板主が板設定として指定する >>1 の定型本文。属性: 本文、所属する板。スレ開設・次スレ移行で >>1 として自動投稿される。変更は次スレから適用(遡及しない)。未設定時はシステム既定の最小テンプレ
- **板設定(拡張)**: 006 の板設定(板タイトル・スレ最大レス数・名無しのデフォルト名・ローカルルール・`first_post_pow_bits`)に、固定 >>1 テンプレを加える。板ページから編集でき(スレ非依存)、BAN 済みエントリの一覧参照・変更(解除等)の管理面もここから到達する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者所有の一般的な Web ブラウザ(専ブラでない)から本ソフトウェアの Web UI を開き、スレ一覧閲覧・スレ閲覧・書き込みが、参考画像 `_alt` と同等の掲示板要素(スレ一覧・スレ立て・ローカルルール掲示・名前/メール/本文欄・レス番号/ID/日付・`>>n` アンカー)を伴って成立する(実機確認)
- **SC-002**: 同一 LAN 上の別端末(視聴端末)の Web ブラウザから、LAN 公開を有効化した稼働端末の実況スレを閲覧・書き込みでき、その書き込みが全端末で同一レス番号として確定する(実機確認)
- **SC-003**: グローバルユニキャスト・未指定(0.0.0.0 / ::)・CGNAT アドレスへの公開設定は 100% 拒否され、LAN 公開は loopback + RFC 1918 / リンクローカル / ULAに限定される
- **SC-004**: 非 loopback での LAN 公開は事前の明示確認(同意)なしには 100% 成立せず(同意のない非 loopback 設定は拒否される)、非 loopback 待受に成功した起動時、公開の事実が 100% セキュリティイベントとして記録される
- **SC-005**: 固定 >>1 テンプレを設定した板で新規スレ・次スレを開設したとき、100% のスレで >>1 が自動投稿され、空 >>1・>>1 不在が 0 件になる
- **SC-006**: 固定 >>1 テンプレの変更後に開始したスレのみ新テンプレが反映され、既存の確定済みスレの >>1 に遡及した変更が 0 件である
- **SC-007**: 別端末からの書き込みを含む多ノードテストで、全端末のレス番号・表示順序・アンカー解決の不一致が 0 件(006 SC-002 の水準を維持する)
- **SC-008**: LAN 公開時の URL/ヘッダサイズ上限・per-IP レート制限が loopback 側と同一に保たれる(保護緩和 0 件)
- **SC-009**: 利用者所有の専ブラを同一 LAN 上の別端末から無改修で本ソフトウェアの LAN 公開した互換 API に向け、スレ一覧取得・レス取得・書き込みが成立し、その書き込みが全端末で同一レス番号として確定する(実機確認)。かつ互換 API のグローバル/CGNAT/未指定アドレスへの公開設定は 100% 拒否される

## Assumptions

- 本機能は 006-livechat-thread の P2P・順序確定・鍵体系・NG/BAN・PoW・レート制限・互換 API を一切変更せず、その上の表現層(Web UI)・公開経路(バインド)・開設時初期状態(>>1)を補うものである
- Web UI のスキンは旧来(`_alt`、伝統的 2ch 風)を標準とする。現代的スキン(`_main`)やスキン切替は本機能のスコープ外(将来検討)
- LAN 公開は明示オプトインであり、既定は loopback のみ(現状の `http_bind` 相当の安全側)。LAN 内を信頼境界とし、別端末書き込みのための追加認証(PIN/QR 等)は課さない。トークンは LAN 内で共有される前提で、平文露出は受容リスクとして明示確認・監査の対象とする
- LAN 公開は ADR-0012(読み取り専用 index.txt の LAN 公開)の許可リスト方式(loopback / RFC 1918 / リンクローカル / ULA、`require_lan_or_loopback` 相当)に準拠する。ただし ADR-0012 は書き込み系(HTTP API / UI)を loopback 強制のまま残したため、本機能は Web UI + JSON API と 2ch 互換 API の LAN 公開(書き込みを含む)を許す新しい決定(新 ADR)を要する。互換 API の無認証 LAN 書き込みの受容もこの新 ADR で明文化する。プロトコル・保護水準は ADR-0012 決定 5(保護の非緩和)を踏襲する
- 2ch 互換 API(`compat_bbs_bind`)も本機能の LAN 公開対象に含める(Clarifications 2026-07-31)。互換 API は設計上トークンを送れないため LAN 書き込みは無認証で受理され、保護は Host 検証・per-IP レート制限・LAN 内アドレス限定・明示オプトイン・起動時 SecurityEvent 記録で担保する(HTML UI と同一方針)。公開面ごとの設定単位(Web UI と互換 API を個別に切り替えるか一括か)は plan で確定する
- 固定 >>1 テンプレは板設定として永続化する(006 の板設定と同じ永続化方針)。スレ本文(>>1 を含む確定レス)は 006 どおり揮発(永続化しない)
- 固定 >>1 テンプレの最大文字数・書式(プレーン/Markdown 安全サブセット等)、および Web UI の具体的な HTML/CSS 構造・アンカー UI(ポップアップ/ジャンプ)・読み出しレンジ(最新 50 / 全部 / 1-100 等)の詳細は plan/contracts で確定する。適合の実勢参照は bbs.jpnkn.com の `_alt`(旧来)デザインとする
- LAN 外(モバイル回線・インターネット越し)からの書き込みはスコープ外。グローバル公開・遠隔アクセスは別途の設計課題とする
- 遠隔公開をしない前提のため、脅威モデル上の主な追加露出は「LAN 内の他端末による平文の読み取り・書き込み・トークン取得」に限られる。これは ADR-0012 が index.txt(読み取り)について受容したリスクに、書き込みを加えたものとして評価する

# Contract: Web UI(旧来 BBS 互換)と JSON API 差分

**Feature**: 007-web-bbs-write | **参照**: [research.md](../research.md) R5/R6、
[data-model.md](../data-model.md)

対象は `ui/livechat.html`(後継)の UI 契約と、それを支える JSON API
(`/api/v1/livechat/...`)の差分。006 の API 契約は明記した差分以外変更しない。

## 1. ページ構成とルーティング

単一 HTML(`GET /livechat.html`、`include_str!` 埋め込み・外部アセット参照なし)の
ハッシュルーティング SPA。

| ルート | ページ |
|--------|--------|
| `#/`(既定) | 板選択(自板 + 参加中の板の一覧。従来のチャンネル選択に相当) |
| `#/board/{board_id}` | 板ページ |
| `#/thread/{board_id}/{thread_key}` | スレページ |

**ナビゲーションリンク(FR-002a — MUST)**: 板選択ビュー(`#/`)の各板項目は
`#/board/{board_id}` へ、板ページのスレ一覧の各項目は `#/thread/{board_id}/{thread_key}` へ、
クリックで遷移できるリンクとする。一覧項目を遷移手段のない静的表示に留めてはならない
(参考 `_alt` 掲示板と同等のナビゲーション)。

## 2. 板ページの要素契約(参考画像 `_alt` 板ページ相当 — FR-001/FR-004)

必須要素(上から):

1. **板タイトル帯**: `BoardSettings.title`(緑帯系の旧来スキン)
2. **ローカルルール掲示**: サーバ側で安全 HTML 化済みの `local_rules_html` を表示
   (クライアントで生の Markdown/HTML を解釈しない — FR-005)
3. **スレ一覧**: 各行 = `{連番}: {スレタイトル} ({確定レス数})`。各行はクリックで
   スレページ(`#/thread/{board_id}/{thread_key}`)へ遷移するリンク(FR-002a)
4. **新規スレ作成欄**: スレタイトル入力 + **>>1 本文入力欄** + 作成ボタン(FR-014a)。
   - >>1 本文欄は板設定の固定 >>1 テンプレ(未設定時はシステム既定テンプレ)を既定値として
     **プリフィル表示**する。板主は開設時に任意で上書きでき、未編集なら既定値が >>1 になる
   - 上書き値は**そのスレの >>1 のみ**へ反映し、板設定の永続テンプレは変更しない
   - 作成は `POST .../open` 系 API(§5.3 の任意 `first_post_override` を付与)を使用。作成後は
     >>1 が確定した状態でスレページへ遷移する(空 >>1 は生じない)
5. **板管理セクション(FR-006a/FR-006b)**: スレの有無・スレ開設操作と独立に、板ページから
   到達できる管理領域(折りたたみ `<details>` 等)。スレ 0 件の板でも操作可能:
   - **板設定編集**: 板タイトル・名無しのデフォルト名・ローカルルール・固定 >>1 テンプレを
     `PUT .../settings` で編集(§5.2)。板設定編集をスレ開設や特定スレの存在に依存させない
   - **BAN 一覧管理**: BAN 済みエントリの一覧参照および変更(解除等)を板ページから到達・
     実行できる(BAN 台帳はスレ非依存)。個別レスへの NG/BAN の**実行**はスレページ起点(§3.7)
6. **専ブラ向け板 URL の掲示**: `http://{location.hostname}:{compat_bbs_port}/{board}/`
   を動的生成して表示(`compat_bbs_port` が null(互換 API 無効)の場合は非表示)。同 URL は
   ブラウザで開くと板ページ(HTML)、専ブラに登録すると `subject.txt` 等を返す(§7・FR-023)

## 3. スレページの要素契約(参考画像 `_alt` スレ last50 相当 — FR-001/FR-002)

1. **スレタイトル帯**
2. **レス列**: 既定は**最新 50 レス**(クライアント側スライス)。各レスは伝統的 2ch 形式:

   ```text
   {res_no} :{名前}:{日付} ID:{id}
   {本文(複数行)}
   ```

   - 名前が空のレスは `noname_name` で表示(FR-004)
   - 各レス要素は `id="res-{res_no}"` を持つ
   - 欠番(NG 非表示)はレス番号を詰めない(006 の欠番維持)
3. **`>>n` アンカー**(FR-002):
   - 本文中の `>>数字` をアンカー要素へ変換(テキストとしてエスケープ後に変換 — FR-005)
   - クリック: `#res-{n}` へページ内ジャンプ(表示範囲外なら全件表示へ切替えてジャンプ)
   - ホバー/タップ: 参照先レスのインラインポップアップ
   - 参照先が未確定・欠番・範囲外(1 未満・確定済み最大超): ジャンプせず「解決不能」表示
     (ポップアップに明示。誤ったレスへ誘導しない)
4. **表示切替**: 「全部読む」で全件表示 / 「最新50」へ戻る
5. **書き込み欄**: 名前(任意)・メール(任意)・本文(必須)+ 書き込みボタン。
   既存 `POST /api/v1/livechat/threads/{board}/write`(202 受理)を使用し、確定反映は
   ポーリング更新で表示(FR-003 — Web UI 専用の検証経路を作らない)
6. **追従表示**: 8 秒間隔の定期更新(既存踏襲)+ 明示更新ボタン(FR-006)
7. **管理操作**(既存機能の温存): 折りたたみ(`<details>`)内に配置。
   - **個別レスのモデレーション実行**(NG/BAN 等)は、対象を見ながら操作できるよう
     スレページ起点で提供する(FR-006b)
   - join/leave/next/close 等のスレ操作もここに配置する
   - **板設定編集・BAN 一覧管理はスレページから外し、板ページの板管理セクション**(§2.5)へ
     移設する(FR-006a — スレ非依存で管理可能にする)

## 4. 安全描画規則(FR-005 — 006 FR-025 と一貫)

- レス本文・名前・メール・スレタイトル・固定 >>1 はすべて**テキストとしてエスケープ**して
  から装飾(アンカー化・改行→`<br>`)する。`innerHTML` への生値挿入禁止
- ローカルルールのみサーバ側安全 HTML(`local_rules_html`)を使用(既存契約)
- 外部リソース(画像・スクリプト・CSS)の読み込みなし。レンガ調背景は CSS/データ URI

## 5. JSON API 差分

### 5.1 板詳細(`GET /api/v1/livechat/threads/{board}`)— フィールド追加

```jsonc
{
  // ...既存フィールド(settings, レス列 等)は変更なし...
  "compat_bbs_port": 7183,        // 追加: 互換 API の待受ポート。無効時は null
  "settings": {
    // ...既存...
    "first_post_template": "..."  // 追加: 固定 >>1 テンプレ(板主向け設定表示用)
  }
}
```

### 5.2 板設定更新(`PUT /api/v1/livechat/threads/{board}/settings`)— フィールド追加

- リクエストに `first_post_template`(string、省略可)を追加。検証は
  [fixed-first-post.md](fixed-first-post.md) §2。検証失敗は既存の板設定検証エラーと
  同形式(400)
- 適用された板設定は SQLite `board_settings` へ永続化される(再起動後も保持)

### 5.3 スレ開設(`POST /api/v1/livechat/threads/{board}/open` 系)— 任意フィールド追加

- リクエストに `first_post_override`(string、省略可)を追加できる(FR-014a)。付与された
  場合、そのスレの >>1 本文として板設定の固定テンプレの**代わりに**用いる。省略/空なら
  従来どおり板設定の固定 >>1 テンプレ(未設定時はシステム既定テンプレ)を用いる
- `first_post_override` の検証は固定 >>1 テンプレと同一(≤2048 文字・≤32 行・制御文字除去 —
  [fixed-first-post.md](fixed-first-post.md) §2)。上限超過は 400
- override はそのスレの >>1 にのみ適用し、板設定に永続化された `first_post_template` を
  変更しない(MUST NOT — 次スレ・他スレには波及しない)
- 自動投稿された >>1(override 有無を問わず)は FR-016 と同一の検証(採番・板鍵署名・
  配布、初回 PoW 免除)を満たす

### 5.4 変更しないもの

- 認証(GET はトークン不要 / 変更系は `X-Api-Token`)・トークン配布(`GET /api/v1/token`)
- レート制限(接続元ごと 20 req/秒)・ボディ上限 — LAN 公開時も同一水準(FR-011)
- 書き込み・次スレ・クローズ・モデレーションの各エンドポイントの意味論(スレ開設の
  >>1 override は §5.3 の任意フィールドのみ)

## 7. 互換 API 面での板ルート URL のブラウザ向け配信(FR-023 — research.md R11)

互換 API 待受面(`compat_bbs_bind`)は、専ブラ向けパスとブラウザ向け板ページを**同一ポート・
同一パス上でパスにより振り分けて**配信する。他面(`http_bind` 等)へのリダイレクトは行わない
(MUST NOT)。

| リクエスト(互換ポート) | 応答 | 文字コード | 用途 |
|--------------------------|------|-----------|------|
| `GET /{board}/`(末尾スラッシュのみ・ファイル名なし) | 旧来 BBS UI の板ページ(HTML)。`{board}` を初期表示板として開く | UTF-8 | Web ブラウザ |
| `GET /{board}/subject.txt` | スレ一覧(既存) | Shift_JIS | 専ブラ |
| `GET /{board}/dat/{key}.dat` | レス取得(既存) | Shift_JIS | 専ブラ |
| `POST /{board}/bbs.cgi`(相当) | 書き込み(既存) | Shift_JIS | 専ブラ |

- ブラウザ向け HTML は Web UI(`http_bind`)と**同一の `include_str!` 資産**を用い、板ページ・
  スレページが互換ポート上で自己完結する(板詳細/書き込み等の JSON API も同一オリジンで到達)
- 専ブラ向けパス(`subject.txt` / `dat` / `bbs.cgi`)の応答・SJIS・検証は**一切変更しない**
- 板ルート URL への HTTP リダイレクト(302 等)で他面の Web UI に飛ばしてはならない
  (公開面ごとの独立オプトインの維持・同一 URL での自己完結 — FR-023、research.md R11)
